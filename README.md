# ⚡ ST-Cache-Optimizer · 酒馆缓存优化

让 SillyTavern 发出去的提示词**两轮之间开头尽量一字不差**，从而命中 Gemini / Vertex AI 的隐式缓存（以及其他按前缀计费的缓存）。缓存命中的输入 token 通常只按原价的一小部分计费（Vertex Gemini 为 1/20）。

**不改任何文件**：世界书、预设、角色卡都原样不动。扩展只在每次生成时现场调整本次请求，关掉开关立即恢复原样。

## 为什么命中率会是 0

Vertex / Gemini 的缓存有两条规则（实测）：

1. **开头的系统提示**（第一条对话消息之前的所有 system 消息）必须**整段一字不差**，差一个字整段都不命中。
2. 系统提示之后的内容按**前缀**命中，遇到第一个不同的字就停。

常见的角色卡和预设恰好违反了第 1 条：

| 每轮都会变的东西 | 常见位置 |
|---|---|
| 关键词触发的世界书条目（提到什么就插入什么） | 角色定义前 / 后 → 系统提示 |
| MVU 等变量块（`<status_current_variables>`）、随机宏、时间宏 | 世界书常驻条目 |
| 记忆扩展的摘要（如柏宝书的「记忆系统私密简报」） | 聊天记录最前面 → 系统提示 |
| 按深度插在聊天记录中间的条目 | 每多一轮位置就后移，改写上一轮的前缀 |

## 它做了什么

1. **世界书现场调整**（`WORLDINFO_ENTRIES_LOADED`，只改本次扫描的临时副本）
   - 角色定义前/后的**关键词条目**、**会变的常驻条目**（MVU 变量、随机/时间宏、概率触发、粘性/冷却/延迟）→ 聊天中深度 0，并用 `<当前剧情相关设定>` 包住。
   - 按深度插入的**关键词 / 会变条目** → 深度 0（深度设得比聊天记录还大时，它们会落进系统提示）。
   - 按深度 / 作者注释插入、**内容固定的常驻规则** → 聊天记录之前：预设的「角色定义前」排在聊天记录前面时放进去，否则插在聊天记录最顶端并用 `<固定设定>` 包住。
   - 输出格式、破限等必须留在末尾的条目保持原位（可在设置里用正则调整）。
   - （可选，默认关）**关键词设定放到聊天记录前并保持几条消息**：关键词条目插在聊天记录最顶端、用 `<近期剧情设定>` 包住，并临时设为粘性 N 条消息（默认 6）。场景稳定时这块几轮不变，它和后面的整段聊天记录都能命中缓存；换场景、设定变化的那一轮，连聊天记录也会不命中。适合长时间待在同一场景的玩法，开几轮对比真实命中率再决定。**Gemini / Vertex 或开启提示词后处理（合并 / 半严格 / 严格）时自动不生效**：这些情况下聊天记录前的 system 块会被并成一条大消息，而 Vertex 实测只在消息边界上命中缓存，设定一变整条大消息都不命中。
2. **发送前重排**（`CHAT_COMPLETION_PROMPT_READY`）
   - 用真实聊天消息比对，认出提示词里真正的聊天记录范围（预设开头的伪造对话、规则、资料都不算）。
   - 聊天记录中间插入的 system 块、聊天记录之前的易变块 → 挪到聊天记录之后，离生成位置最近，注意力也最高。
3. **自动学习**：系统提示里某一块两轮之间内容变了，就记下它的开头，以后自动挪到聊天记录之后，适配陌生预设。
4. **真实发送对比**：在网络层旁观每次真实发出的请求（不修改、不额外请求），和同一聊天的上一次对比，报告整条相同的前缀比例和第一处不同的位置；能发现模拟看不到的变化（EJS 渲染、生成时注入、变量被脚本改写等）。结果显示在面板里并存进设置。
5. **免费稳定性检查**：只组装、不发送，模拟「上一轮」和「这一轮」的提示词，报告系统提示是否一致、两轮相同前缀的比例、第一处不同在哪里。

## 安装

酒馆 → 扩展程序 → 安装扩展程序，填入本仓库地址；或把本目录放到
`public/scripts/extensions/third-party/ST-Cache-Optimizer/`，刷新页面。

## 使用

- **开关**：左下角魔法棒菜单里的「缓存优化：开/关」，点一下即可开启或关闭（关闭时闪电图标变暗）；扩展设置面板里也有勾选框。
- 换了新卡 / 新预设后，点「检查缓存稳定性（免费）」：
  - 「系统提示两轮一致」是 ✅ 才能命中；❌ 时会列出变化的块。
  - 「两轮相同的前缀」越高越省。
- 搭配记忆扩展时，让旧楼**攒批折叠**（每 N 轮折叠一次）而不是逐楼滑动，聊天记录开头才能保持不变。

## 实测（Vertex AI · gemini-4-argon，一张约 14 万 token 的长卡）

| | 命中缓存 |
|---|---|
| 优化前 | 0%（连续 30 多轮） |
| 优化后 | 40.2%（142,701 中 57,344） |

免费检查（只组装不发送）中，两轮相同的前缀：

| 卡 | 关闭 | 开启 |
|---|---|---|
| 命定之诗与黄昏之歌（大型世界书 + MVU + 柏宝书） | 6.8%，系统提示 ❌ | 70.3%，✅ |
| 另一张带世界书的卡（深度 10000 的动态条目） | 7.0%，系统提示 ❌ | 68.1%，✅ |
| 无世界书的卡 | 50.0% | 50.0%（无副作用） |

## 注意

- Vertex 隐式缓存实测：间隔 1～12 分钟都能命中，20 分钟已过期。

- 只支持对话补全（Chat Completion）接口。
- 改设置 / 切换预设 / 开关条目后的第一轮一定不命中；两轮间隔太久缓存会过期。
- 关键词条目默认移到了聊天记录之后（开启「保持几条消息」后改为聊天记录之前，与多数预设原本的位置一致），模型参考它们的位置变了，一般影响很小；介意的话关掉「世界书现场调整」即可。
